In simple words:
- Synchronous: Code executes one task at a time. The next task waits until the current task finishes.
- Asynchronous: A task can start and allow other code to run while waiting for the task to finish.

12. how does node js mainatin concurency even afer being single threded?
ans:
Node.js maintains concurrency even though JavaScript runs on a single main thread by using the Event Loop, asynchronous operations, 
and the operating system (OS) or libuv thread pool.

Node.js maintains concurrency through its event-driven, non-blocking architecture. 
The JavaScript code runs on a single main thread, while asynchronous I/O operations are handled by the operating system or libuv's thread pool, depending on the operation. 
The event loop coordinates the execution of callbacks when operations complete.
 This allows Node.js to handle multiple requests efficiently without creating a separate JavaScript thread for each request

 14. Event Loop?
 ans:
 The Event Loop in Node.js is a mechanism that allows Node.js to handle multiple tasks efficiently
  without blocking the main thread while waiting for operations like API calls, file reading, or database queries to finish.

  In simple words, 
  the Event Loop checks whether asynchronous tasks are completed and executes their callbacks when the main thread is available.

  Final rule to remember:
- Synchronous JavaScript runs first.
- process.nextTick has special scheduling priority in typical CommonJS execution.
- Promise reactions and other microtasks run at microtask checkpoints.
- Timer, I/O, and setImmediate() callbacks run in their respective Event Loop phases.
- Microtasks created inside callbacks are processed before normal event-loop processing continues.


15.disadvantages of node js?
ans:
1.Node.js has some limitations. First, it is not ideal for CPU-intensive tasks because heavy computations can block the Event Loop and delay other requests.
2.Second, complex asynchronous code can become difficult to maintain, although Promises and async/await help solve this problem.
3.Third, its large npm ecosystem can introduce dependency and security risks. However, we can address these issues using Worker Threads, background jobs, proper error handling, and secure dependency management.

What is Event-Driven Programming in Node.js?
ans:
Event-driven programming is a programming approach in which the execution of a function depends on an event occurring.

In simple words, when something happens, such as a user clicking a button, a file finishing reading, or a request arriving, the corresponding function is executed.

Node.js uses event-driven programming extensively to handle asynchronous operations and events.

"Event-driven programming is a programming approach where functions are executed in response to events.
 Node.js uses this approach extensively for asynchronous I/O and event handling.
  For example, we can use the built-in EventEmitter module to register listeners with on() and trigger events with emit().
   This approach helps Node.js handle incoming requests and other asynchronous activities efficiently."

Remember: on() registers an event listener, while emit() triggers an event.

const EventEmitter = require("node:events");

// Create an event emitter
const event = new EventEmitter();

// Register an event listener
event.on("hello", () => {
  console.log("Hello! Event occurred.");
});

// Trigger the event
event.emit("hello");

Node.js provides the built-in Buffer class.
